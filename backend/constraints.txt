# Full transitive dependency graph, pinned.
#
# requirements.txt carries the direct dependencies with `>=` floors, which is what
# you want when reading the project's intent. It is a bad thing to build from on its
# own: every rebuild re-resolves the whole graph against whatever PyPI happens to
# hold that day, so two builds of the same commit can ship different code. This file
# closes that gap by pinning the complete graph - direct and transitive - so a given
# commit always produces the same image.
#
# These pins were captured with `pip freeze` from the image running in production
# (revision ca-pixelslime-api--0000019), so adopting this file changes nothing about
# what gets installed. It only stops the graph from drifting on the next build.
#
# To regenerate after intentionally moving a dependency:
#   docker run --rm <image> pip freeze > backend/constraints.txt
# or, against the live app:
#   az containerapp exec -n ca-pixelslime-api -g <rg> --command "pip freeze"
#
# NOTE ON eth_abi: production resolved to 6.0.0b1, a pre-release, because the
# unpinned graph allowed it - web3 7.16 has no stable eth-abi 6.x to fall back on.
# It is pinned here as-is so this file stays a faithful record of what runs today
# rather than an untested change. It encodes the ABI payload of every anchoring
# transaction, so moving it needs a deliberate test run against Amoy, not a bump.
