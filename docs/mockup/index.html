🌧 THE GREAT PIXEL RAIN

A rainbow crashed above the clouds and it rained pixels. Wherever a pixel touched something happy, the thing went soft, wobbled twice, and opened two shiny eyes.

🍵 THEY EAT MOODS

A slime absorbs the atmosphere around it. Nap in a sunbeam, become golden. Grow up in a library, become clever and quiet. Meet a cat, learn to purr.

⏰ ONE PER DAWN

Exactly one slime condenses each day. Keepers must catalogue it before it drifts away — that's why the SLIMEDEX exists.

RARITY TIERS

Rolled in code with a seeded weighted random — never left to the model. A pity timer forces a ≥ RARE roll if 14 days pass without one.

THE 16 TYPES

Four bits, sixteen moods.

HOW A CARD IS BORN

1 · ROLL

Rarity, biome, mood and companion are drawn in code from a seed derived from the date. Reproducible.

2 · WRITE

gpt-5.6-sol writes the card as strict JSON — name, personality, power, stats — length-capped so it fits the byte budget.

3 · PAINT

gpt-image-2 paints the card at 1024×1536 with a transparent background, using this very template as the style reference.

4 · CHECK

A vision model reads the finished card back and verifies every number matches the JSON. Mismatch → repaint.

5 · PACK

The card is packed into PSC-1: 32-byte header + dictionary-DEFLATE text, Z85-encoded into asmDB rows of 175 bytes.

6 · ANCHOR

Phase 2 — the packed bytes are hashed and minted on-chain as proof the slime existed exactly like this, on that day.

⛓ WHAT IS ACTUALLY ON-CHAIN

Not the picture, and not the JSON. The 175 packed PSC-1 bytes, hashed with keccak256 into an ERC-721. The chain proves the slime existed exactly like that, on that day — without duplicating a single byte of it.

🔐 WHO SIGNS

An Azure Key Vault secp256k1 key. Non-exportable, signed through the HSM with a managed identity. The private key exists nowhere in the code, the env or the logs.

🧪 WHERE

Polygon Amoy testnet first — free faucet gas, so the whole loop can run for as long as we like before anyone decides whether real money is ever involved.
